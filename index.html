System overview

What Washioo does

Washioo is a doorstep vehicle wash platform. Customers book car or bike wash services, cleaners receive nearby work based on approval, availability, and location, and admins control service setup, booking assignment, verification, payments, reports, and platform health.

Customer

Book and track service

Customers verify phone number, choose a service, save address and vehicle details, schedule the wash, track status, view cleaner details, and rate after completion.

Cleaner

Accept and complete jobs

Cleaners sign up with identity documents, wait for approval, go available with live location, accept assignments, start service, complete service, and record cash or UPI collection.

Admin

Operate the platform

Admins approve cleaners, manage services, monitor bookings, retry auto assignment, manually assign when needed, reconcile payments, export data, and review ratings.

Backend

Secured API layer

The backend provides OTP authentication, role access, bookings, addresses, cleaner verification, auto assignment, payments, ratings, notifications, and admin reporting under /washioo-api.

Booking lifecycle

From booking to payment close

This is the main operational flow everyone should understand. Most support questions can be answered by locating the booking in this lifecycle.

1
Customer creates booking Select service, address, vehicle, date/time, and optional instructions. Unsaved checkout addresses are saved before booking.
2
System tries auto assignment Eligible cleaners must be approved, available, auto assignment enabled, recently located, and inside service radius.
3
Cleaner accepts or rejects If accepted, the job moves forward. If rejected, the backend offers it to the next eligible cleaner automatically.
4
Cleaner starts and completes Cleaner can open route, start service, enter collected amount, choose cash or UPI, and mark the service completed.
5
Admin reconciles payment Admin reviews collected payments, enters cleaner share, confirms admin share, and marks admin collection settled.

Customer manual

How customers use Washioo

Customers should complete the steps in order. The most important rule is simple: save a complete address with live location before expecting clean assignment and routing.

Step 1

Verify phone

  1. Open the app and choose customer account type.
  2. Enter a valid 10-digit Indian mobile number.
  3. Accept the terms and continue.
  4. Enter the OTP received by SMS.
Existing customers go to sign in. New customers go to sign up and enter name, optional email, and OTP.
Step 2

Manage address

  1. Go to Addresses.
  2. Add label, street, city, state, and pincode.
  3. Use Live Location so the cleaner can find the service point.
  4. Set the most used address as default.
If browser location permission is blocked, booking assignment can fail or routing may be inaccurate. Enable location and save again.
Step 3

Manage vehicles

  1. Go to Vehicles.
  2. Add bike or car, make, model, and license plate if available.
  3. Mark the regular vehicle as default.

Vehicle details are optional during checkout, but adding them helps the cleaner identify the vehicle quickly.

Step 4

Book service

  1. Open Book Service or Bookings.
  2. Select the required service category.
  3. Confirm address, optional vehicle, date, time, and notes.
  4. Click Confirm Booking.
  5. Track booking from My Bookings.
After a cleaner accepts, customer booking details can show the cleaner name, profile photo, rating, experience count, and verification badge.
Step 5

After completion

  1. Check payment status after cleaner marks service completed.
  2. View whether payment was recorded as cash or UPI.
  3. Rate the cleaner from the completed booking details.

Customer support checklist

  • Phone number should be 10 digits without country code.
  • Terms must be accepted before OTP flow continues.
  • Address must include live latitude and longitude.
  • Booking date and time must not be in the past.
  • If no cleaner is assigned, admin can retry Auto Assign.
  • Rating appears after booking status is completed.
Cleaner manual

How cleaners handle work

Cleaners only become eligible for auto assignment after document approval, availability update, and location sharing.

Step 1

Cleaner signup

  1. Choose cleaner account type in phone verification.
  2. Enter phone number, accept terms, and verify OTP.
  3. Provide full name, optional email, Aadhaar number, profile photo, and Aadhaar image.
  4. Add driving license number and image when required or available.
Image uploads accept JPG, PNG, and WebP. The default maximum file size is 3 MB unless backend configuration changes it.
Step 2

Wait for approval

  1. Open Profile to check document review status.
  2. If admin requests resubmission, read the reason shown in Profile.
  3. Upload corrected profile photo, Aadhaar, or license documents.
Availability and booking acceptance are blocked until the cleaner profile is approved.
Step 3

Go available

  1. Open Cleaner Dashboard or Availability.
  2. Allow browser location access.
  3. Set status to Available.
  4. Keep the app/browser available so location can refresh.

The dashboard refreshes cleaner location every few minutes when the cleaner is approved and available.

Step 4

Handle assignment

  1. Open My Assignments.
  2. Use tabs: assigned, accepted, in progress, completed, rejected.
  3. For new assigned work, click Accept or Reject.
  4. After accepting, open route and go to the customer address.
  5. Click Start Service before beginning work.
If a cleaner rejects a booking, the backend records the attempt and immediately tries the next eligible cleaner.
Step 5

Complete and collect

  1. Enter the final collected amount.
  2. Select payment type: cash or UPI.
  3. Click Complete Service.
  4. Rate the customer after completion.
  5. Check earnings after admin reconciles payment.

Cleaner eligibility rules

  • Approval status must be approved.
  • Availability status must be available.
  • Auto assignment must be enabled for the cleaner profile.
  • Current latitude and longitude must be present.
  • Location must be updated within the freshness window.
  • Booking address must have latitude and longitude.
  • Cleaner must be inside service radius.
Admin manual

How admins operate Washioo

Admins are responsible for keeping the platform moving: approved cleaners, active services, assigned bookings, reconciled payments, clean data, and export-ready reporting.

Dashboard

Platform overview

View total bookings, pending jobs, active jobs, completed jobs, cleaner counts, available cleaners, revenue, recent bookings, and Excel exports.

Bookings

Assignment control

Search bookings, filter by status, view customer and service details, retry Auto Assign for pending bookings, or manually assign an available cleaner.

Cleaners

Verification and availability

Review identity documents, approve, reject, request resubmission, suspend/reactivate cleaners, and adjust cleaner availability when business support needs to intervene.

Services

Service catalog

Add or edit service categories, base price, duration, active state, service image, and optional extra payment instructions.

Payments

Reconciliation

Review collected payments, split cleaner and admin shares, and mark admin share as collected from the cleaner.

Reports

Exports and review

Download full or dataset-specific Excel workbooks covering users, cleaners, bookings, ratings, and payments for offline review.

Daily routine

Start of day

  1. Open Admin Dashboard and check pending bookings.
  2. Check approved and available cleaner count.
  3. Review new cleaner profiles and pending document updates.
  4. Confirm service categories are active and priced correctly.
During operations

Booking support

  1. Use the Bookings page status tabs to find pending, assigned, accepted, in progress, completed, or cancelled work.
  2. For pending bookings, click Auto Assign first.
  3. Use manual assignment only when the auto pool is exhausted, cleaners are offline or busy, location is missing, or support must override.
  4. After completion, direct payment questions to the Payments page.
Payment close

End of day

  1. Open Payments and filter collected payments.
  2. Enter cleaner share. Admin share is calculated from collected amount.
  3. Confirm split.
  4. When admin receives the admin share from cleaner, mark it collected.
  5. Download exports when finance or management needs reports.

Cleaner document review actions

  • Approve: Use when identity and required images are valid.
  • Reject: Use when cleaner should not proceed. A reason is required.
  • Request resubmission: Use when the cleaner can correct missing or unclear documents. A reason is required.
  • Suspend: Use for approved cleaners who should temporarily stop receiving work.
  • Reactivate: Move suspended cleaners back to approved when ready.
Operations reference

Status, backend, and data flow

These tables help support teams explain what is happening behind the screen and what action should be taken next.

Booking statuses

Status Meaning Who acts next
pending Booking created, no cleaner accepted yet. System auto assignment or admin retry/manual assign.
assigned Cleaner has been offered the booking. Cleaner accepts or rejects.
accepted Cleaner accepted and should travel to service location. Cleaner opens route and starts service.
in_progress Cleaner started the service. Cleaner completes service and records collection.
completed Service is finished. Customer/cleaner rating, admin payment reconciliation.
cancelled Booking no longer active. Support reviews reason if needed.

Payment statuses

Status Meaning Action
pending_collection No completed collection recorded yet. Cleaner completes service and enters amount.
collected Cleaner recorded cash or UPI collection. Admin enters cleaner share and confirms split.
split_done Cleaner/admin shares are calculated and saved. Admin collects admin share from cleaner if pending.
settled Admin share has been collected. No payment action required.

Backend architecture in plain words

  • Routers: API endpoints for auth, services, customer, cleaner, admin, payments, ratings, and realtime sockets.
  • Services: Business rules such as OTP, booking lifecycle, cleaner assignment, payments, ratings, notifications, and storage.
  • Repositories: Database access for users, bookings, cleaners, payments, addresses, vehicles, notifications, and assignments.
  • Models: PostgreSQL-backed SQLAlchemy models for core data.
  • Schemas: Pydantic request and response shapes used by the API.
  • Migrations: SQL migration files define schema changes like vehicles, payment splits, auto assignment, push notifications, and document verification.

Support playbook

Common issues and quick fixes

Use this section when someone says, "It is not working." Start with their role, then locate the exact stage of the workflow.

Customer cannot receive or verify OTP
  1. Confirm phone number is 10 digits without country code.
  2. Confirm terms checkbox is selected before sending OTP.
  3. Ask user to wait for resend cooldown before requesting again.
  4. Check SMSCountry credentials and credits if OTP delivery fails globally.
Booking stays pending
  1. Check if booking address has latitude and longitude.
  2. Check if approved cleaners are available and recently located.
  3. Ask admin to click Auto Assign.
  4. If auto assignment skips, manually assign an available cleaner only after checking availability and distance.
Cleaner is not receiving jobs
  1. Confirm cleaner approval status is approved.
  2. Confirm cleaner is set to available, not offline or busy.
  3. Confirm browser location permission is allowed.
  4. Confirm cleaner is inside service radius and location is fresh.
Cleaner documents are rejected or pending
  1. Admin should open cleaner details and write a clear reason.
  2. Cleaner should re-upload corrected image and number from Profile.
  3. Admin should approve after validating photo, Aadhaar, and license if required.
Payment does not show as settled
  1. Confirm cleaner completed service and entered collected amount.
  2. Admin opens Payments and confirms split.
  3. Admin marks admin share collected after receiving it from cleaner.

Handover checklist for clients

  • Share app URL and this manual URL/file.
  • Explain the three roles before showing screens.
  • Create one test customer booking together.
  • Create or approve one cleaner profile.
  • Show Auto Assign and manual assignment fallback.
  • Complete one test service and reconcile payment.
  • Show exports and where support should check statuses.
  • Confirm who owns SMS, Supabase storage, database, and deployment credentials.
Keep admin access limited. Admin users can approve cleaners, change services, update bookings, reconcile payments, and export sensitive operational data.
